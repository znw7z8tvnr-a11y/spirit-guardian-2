# 獨立優化批次：背包分類單次掃描

切換分類時，inventory_view 改用 inventory_filter.snapshot 一次取得目前分類的實體 ID 清單與全部分類數量，取代分開建立清單、再逐類掃描計數的流程。「可裝配」快照不再對同一批物品重複做裝配判斷。

每個快照對每件非當前物品最多呼叫一次 equipment_error，當前物品仍排除於可裝配；四個分類保留取得順序、實體物品 ID、全部分類的清空選項與計數規則。只需要計數時不建立四份分類 ID 清單。公開 ids 入口維持既有行為，未加入持久快取，下一次操作仍會重新反映裝備變更。

候選預覽及實際確認仍獨立驗證，沒有為了省運算跳過所有權與連線檢查；主畫面的 debug 計數仍按既有時機更新。因此不將「快照中一次驗證」誇大成整個 UI 生命週期只驗證一次。

另修正無效格位的全部數量從 -1 改為 0；無模型時安全回傳空清單／零數量。正常格位的結果保持原樣。

修改 inventory_filter.gd、inventory_view.gd 及 inventory_filters.gd。Godot 4.6.3 匯入、Lab 解析與 inventoryfilters 35／inventory 25／tree 75／touch 20，共 155 項檢查通過。新增測試對照四類原 ID 清單與計數、用代理模型計數驗證次數、無效格位、缺失模型，以及結果不污染物品／配置／亂數或下次結果。Python 選測與錯誤處理 24 項通過。

Web 結果以 browser-single-scan.json 為準，未產生時不可當成通過。沿用真正背包的橫直向分類、分頁、候選取消、替換、物品返回、觸控拖曳與背景樹遮擋回歸；不重跑完整 20 波或全部技能。

本批不改戰鬥、掉率、獎勵、存檔格式或字型；獨立保存，不移動既有標記或更新線上站。尚未量測 iPad FPS 或實機 Safari；美術仍是既有暫用素材。
