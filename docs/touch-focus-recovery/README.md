# 獨立優化批次：觸控失焦恢復

背包與連鎖樹在收到 Godot 視窗失焦、應用程式失焦或背景暫停通知時，清除自訂拖曳手指與進行中狀態，並取消物品卡／樹節點的未完成按壓。即使沒有收到原手指的放開事件，新觸控仍可開始；原手指殘留的拖曳不能繼續帶動畫面。

保留候選、捲動位置、裝備、連線與亂數；沒有新增遊戲自動暫停、自動存檔或恢復半途戰鬥的機制。正常點選、閾值、第二指限制與面板遮擋規則保持不變。

修改 inventory_view.gd、tree_view.gd、其兩份原生測試及兩份既有瀏覽器測試，沿用局部驗收依賴；沒有修改戰鬥核心、字型或素材。

先以新增測試重現背包遺留手指狀態，before-fix-inventory.log 是預期失敗的回歸證據，不是本批通過結果。修正後 Godot 4.6.3 匯入與 Lab 解析，以及 inventory 36／inventoryfilters 35／tree 79／touch 20 共 170 項相關檢查通過；Python 選測與錯誤處理 24 項通過。

新增原生案例包含視窗失焦清理與預覽／裝備／捲動保留、忽略舊拖曳、新手指恢復，以及應用失焦／背景暫停通知都清理新啟動的手勢；完整測試沒有重跑 20 波或全部技能。

Web 以 browser-tree/tree-editor-web.json 與 browser-inventory/browser-focus-recovery.json 為準，未產生時不得當成已通過。用 Chromium CDP 實際觸控拖曳，途中呼叫 canvas.blur() 並派送 window blur，復焦後確認舊拖曳停止及新拖曳可用。樹跑橫直向，背包失焦探針放在短橫向，另保留原橫直向背包回歸。這是瀏覽器焦點事件模擬，不是 iPad OS 真正切 App 或鎖屏驗收，也不注入遊戲狀態。

獨立保存本批，不移動先前標記或更新線上試玩站。實機 Safari／App 切換仍待驗收，美術仍是既有暫用素材；截圖若提供均為實際遊戲。
