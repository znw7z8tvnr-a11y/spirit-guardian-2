# 前五波與第一首領驗收

本輪依優先順序驗收正常開局，保留原 HTML、M2.1 與實驗入口 /lab/。

## 實際修正

1. 接上原 Boss 的 summon_requested 訊號。階段二與召喚招式產生實際小怪，共用正常敵人 AI、傷害、死亡與血肉介面。全場上限 40，不扣原排程怪數；首領死亡後拒絕遲到的召喚。
2. 加入首領生命條、階段、招式中文名稱與蓄力倒數。原場上預警仍保留，沒有宣稱已完成最終 Boss 美術。
3. 一批獎勵領完後開啟配置頁並維持暫停，玩家按「完成配置／繼續戰鬥」才恢復。八倍速時也有足夠裝配時間；不自動替換持有物品。
4. 兩個可達技能的短連鎖間隔上限調為 1.8 秒，單技能仍為 1.1 秒，三個以上保留節奏預設。原本兩技能也等 3.8 秒，會讓初期增加技能反而降低基本出手效率。飛行、接續延遲與單輪不可重疊的限制不變，這不是所有技能的 DPS 保證。

沒有更改本輪的怪物生命／傷害基礎數值或血肉成本；先補上缺失機制與配置流程，不因少數樣本就宣稱平衡完成。

## 驗證範圍

原版基線三種種子能到第六波，但首領召喚沒有接入。本輪原生引擎三種種子，全部從奧彈開局、不載入套裝，只選取實際獎勵、合法配置與自動血肉成長，戰鬥通過第五波首領並完成第六波，到達第七波。

原生固定種子結果：12032、24064、32012；實際首領均進入第三階段、發動 2～4 次攻擊，召喚 3～6 隻小怪。核心保留 100，城牆最低約 94.0%～95.2%，因此目前前期屬於偏寬鬆的新手難度，不能推論後期也平衡。

- tests/first_boss.gd：實際三種種子戰鬥、召喚介面、上限、防重複血肉、首領 HUD、配置暫停、短連鎖與後續跳怪。
- tools/test_first_boss_web.py：橫／直向實際 WebGL，以觸控完成第三波寶石入庫、裝配、首領戰、Boss 獎勵、技能裝配、下一波連鎖。沒有注入血量、傷害、物品或跳波。
- 保留其他引擎、背包、共振、領獎、血肉與倍速回歸測試，記錄見 docs/first-boss/。
- 所有 PNG 均為實際遊戲截圖。Linux Chromium 軟體 WebGL 觸控模擬不是 iPad Safari 實機測試。
